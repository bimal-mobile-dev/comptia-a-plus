- **28% weighting — the single heaviest domain across both Core exams.** CompTIA's V15 refresh deliberately pushed this exam toward a "diagnose the symptom, connect it to the right subsystem" support-workflow model — this domain is where that shows up most directly

## Applying troubleshooting methodology

- While CompTIA's formal troubleshooting methodology steps aren't individually tested as a memorized list in V15, the underlying discipline (identify symptoms → isolate the likely cause → test → resolve → verify → document) is exactly what these scenario-based questions expect you to apply in practice
- Scenario questions typically describe symptoms (a specific error, unusual behavior, or failure) and ask for the most likely cause or the correct next diagnostic step — not a name-the-part recall question

## Hardware troubleshooting scenarios

- **Common hardware failure symptoms**: recognizing what specific symptoms (unusual noises, overheating, boot failures, display artifacts) point to which failing component
- **Component-level diagnosis**: connecting a described symptom back to the specific subsystem (power, storage, memory, cooling) most likely responsible — directly building on the component knowledge from the Hardware domain

## Network troubleshooting scenarios

- **Connectivity failure diagnosis**: given a described network problem (no internet access, intermittent connection, slow speeds), identifying the most likely cause and correct troubleshooting step, applying the protocols and hardware knowledge from the Networking domain
- **Wireless-specific troubleshooting**: diagnosing common wireless issues (interference, weak signal, authentication failures) distinct from wired network problems
